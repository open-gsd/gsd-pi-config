# Phase 1 — UI Design Contract

> Visual and interaction contract for **Foundation, Isolation & Theme Bridge**.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope is foundation only: tokens, CSS isolation, theme dual-write, Button primitive.
> Page chrome, forms, modals, and full Button language rollout are later phases.

## Spacing Scale

Declared values (multiples of 4 only). Align with shadcn default density (`--radius` 0.625rem / 10px family) and existing 40px control height habit where hit targets matter.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline padding |
| sm | 8px | Compact control internal gaps |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Radius (shadcn defaults — locked for web):**

| Token | Value | Usage |
|-------|-------|-------|
| `--radius` | `0.625rem` (10px) | Root radius token |
| `rounded-md` | `calc(var(--radius) - 2px)` ≈ 8px | Buttons, inputs (later) |
| `rounded-lg` | `var(--radius)` ≈ 10px | Cards/panels (later) |
| `rounded-xl` | `calc(var(--radius) + 4px)` ≈ 14px | Large surfaces (later) |

**Exceptions:**

- Minimum interactive hit target: **40px** height for buttons (maps to shadcn `size="default"` / `h-9`–`h-10` family — use default size; prefer **≥36px** rendered height, **≥40px** preferred for primary chrome actions when mounted).
- Icon-only controls (when added later): **40×40px** minimum; Phase 1 Button `size="icon"` must keep 36–40px square.
- Desktop legacy may keep existing 6px/12px radii via `gsd-*` — **do not change desktop radius this phase**.

## Color

### Strategy

- **Web (this phase):** Clean **shadcn neutral** semantic tokens (OKLCH + CSS variables). No GSD cyan primary override.
- **Desktop (this phase):** Unchanged `--gsd-*` palette via `index.desktop.css`.
- **60 / 30 / 10 split (web):**

| Role | Share | Token(s) | Usage |
|------|-------|----------|-------|
| Dominant (60%) | 60% | `--background`, `--foreground` | Page canvas, body text |
| Secondary (30%) | 30% | `--card`, `--muted`, `--secondary`, `--border` | Elevated surfaces, subtle fills, dividers |
| Accent (10%) | 10% | `--primary`, `--ring` | Primary Button fill, focus ring |
| Destructive | semantic only | `--destructive` | Destructive Button variant only |

### Semantic tokens (must exist on web)

Light (`.light` / default `:root` without `.dark`) and dark (`.dark`) must define at least:

| Token | Role |
|-------|------|
| `--background` | Page / app background |
| `--foreground` | Primary text |
| `--card` / `--card-foreground` | Elevated surface |
| `--popover` / `--popover-foreground` | Overlay surface (ready for later phases) |
| `--primary` / `--primary-foreground` | Primary actions (Button default) |
| `--secondary` / `--secondary-foreground` | Secondary fills |
| `--muted` / `--muted-foreground` | Subtle backgrounds / secondary text |
| `--accent` / `--accent-foreground` | Hover/selected subtle accent (neutral, not cyan) |
| `--destructive` | Destructive actions / errors |
| `--border` | Borders |
| `--input` | Input borders (ready for Phase 2+) |
| `--ring` | Focus ring |
| `--radius` | Radius root |

Use **official shadcn neutral OKLCH scaffold** values from CLI/manual install docs (paste as-is). Do not hand-tune toward GSD cyan in Phase 1.

**Accent reserved for (web, Phase 1):**

1. `Button` `variant="default"` (primary) fill and hover
2. Focus **ring** (`--ring` / `ring-ring`) on interactive primitives
3. *Not* for every border, card chrome, or body link restyle this phase

**Destructive reserved for:**

1. `Button` `variant="destructive"` only in Phase 1
2. Future error banners/forms (Phase 2–4) — token must exist now; surfaces not restyled yet

### Explicit non-goals for color (Phase 1)

| Do not | Why |
|--------|-----|
| Map `--gsd-accent` (#22d3ee) → `--primary` | PROJECT: clean shadcn defaults; cyan is post-MVP token tweak |
| Ship shadcn tokens on desktop CSS entry | ISO-01 |
| Restyle existing `gsd-btn` / cyan primary on shared chrome | Phase 2 |
| Glass cards, gradient text, pure `#000`/`#fff` brand hero | DESIGN.md anti-patterns + clean defaults |

### Approximate 60/30/10 reference (neutral — not brand hex lock)

Executor should prefer **OKLCH variables from scaffold**, not hard-coded hex in components. For checker readability:

| Role | Light (approx) | Dark (approx) |
|------|----------------|---------------|
| Dominant bg | near-white neutral | near-black neutral (~oklch 0.145) |

| Destructive | red OKLCH destructive | red OKLCH destructive |

## Button Variants Contract

Phase 1 installs **only** shadcn `Button`. This is the canonical web button API going forward (full site adoption Phase 2 / WEB-06).

### Variants (must match CVA from CLI `button`)

| Variant | Visual | Use when |
|---------|--------|----------|
| `default` | Solid `--primary` fill, `--primary-foreground` text | Primary CTA |
| `secondary` | Solid `--secondary` fill | Secondary actions |
| `destructive` | Solid `--destructive` fill | Irreversible / destructive actions |
| `outline` | Transparent + border | Tertiary / cancel-adjacent |
| `ghost` | No border, hover muted fill | Low-emphasis toolbar actions |
| `link` | Text-only, underline on hover | Inline navigation-style actions |

### Sizes

| Size | Intent |
|------|--------|
| `default` | Standard actions (default for proof) |
| `sm` | Dense chrome (later) |
| `lg` | Emphasized empty-state CTAs (later) |
| `icon` | Icon-only; square hit target |

### Interaction states (required)

| State | Behavior |
|-------|----------|
| Hover | Variant-defined background/border shift; no layout jump |
| Active / press | Slight darken or scale only if CLI default includes it; respect `prefers-reduced-motion` |
| Focus-visible | Ring via `--ring`; never remove outline without replacement ring |
| Disabled | `pointer-events-none`, reduced opacity (~50%); no hover affordance |
| Loading | **Out of Phase 1** (no Spinner primitive yet) — do not invent ad-hoc spinners on Button |

### Phase 1 mounting rule

- Button may be **import-only** (build/`tsc` proof) or a temporary web-only smoke mount.
- **Do not** replace `gsd-btn` / `uiClasses` buttons across the app in Phase 1.
- **Do not** import `@/components/ui/*` from desktop-only or shared domain modules that desktop bundles will pull (prefer web-only files or unmounted module import tests).

### Mapping (legacy → future, not implemented Phase 1)

| Legacy | Future shadcn |
|--------|----------------|
| `btnPrimary` / `.gsd-btn-primary` | `Button variant="default"` |
| `btn` / `.gsd-btn` | `Button variant="outline"` or `secondary` |
| `btnDanger` | `Button variant="destructive"` or outline+destructive treatment |
| Segment theme control | Phase 2 shadcn-styled toggle (not Button dump) |

## Theme Toggle Visual Contract

**Phase 1 responsibility:** dual-write readiness + token correctness — **not** full visual restyle of the control (THM-04 is Phase 2).

### Behavior (locked — preserve)

| Item | Contract |
|------|----------|
| Preference values | `system` \| `dark` \| `light` |
| Labels (user-visible) | **Auto** / **Dark** / **Light** |
| Storage key | `gsd-pi-config.theme` (single authority — no second key) |
| API | Existing `getStoredTheme` / `resolveTheme` / `applyTheme` / `bootstrapTheme` / `useTheme` |
| No-flash boot | `bootstrapTheme()` before React paint (keep order in `main.tsx`) |
| ARIA | `role="radiogroup"` `aria-label="Theme"`; each option `role="radio"` + `aria-checked` |
| Titles | "Follow system theme" / "Force dark theme" / "Force light theme" |

### Dual-write application (THM-03)

`applyTheme(effective)` **must**:

1. Set `document.documentElement.dataset.theme = effective` (`"dark"` \| `"light"`) — keeps GSD / desktop CSS working.
2. Toggle class `dark` on `<html>` when `effective === "dark"`; remove when light.
3. Optionally toggle exclusive `light` class for docs parity — allowed; not required if `.dark` absence means light.
4. **Not** introduce `next-themes` or a second ThemeProvider storage.

Web CSS **must** include:

```css
@custom-variant dark (&:is(.dark *));
```

so shadcn utilities resolve under `.dark`.

### Visual (Phase 1)

| Surface | Expectation |
|---------|-------------|
| Desktop ThemeToggle | Unchanged segmented `gsd-btn-segment` look |
| Web ThemeToggle | May still use legacy segment classes until Phase 2; **must** still flip both token systems |
| Proof | If Button is mounted on web, default Button colors flip with Auto/Dark/Light |

### Phase 2 boundary (do not implement now)

- Restyle ThemeToggle with shadcn controls (ToggleGroup / Button group) without changing semantics (THM-04).

## Isolation Rules

Hard constraints for ISO-01 / FND-04.

### Desktop must NOT inherit

| Forbidden on desktop entry / bundle | Reason |
|-------------------------------------|--------|
| `@import "shadcn/tailwind.css"` | Restyles base layers |
| shadcn semantic OKLCH token block / `@layer base` body rules | Forces new look |
| `@import "tw-animate-css"` (unless already needed independently) | Web animation stack |
| Runtime import of `src/components/ui/**` | Pulls shadcn primitives |
| Global replacement of `gsd-*` tokens with shadcn names | Milestone deferral |

### Web must NOT pull (Phase 1)

| Avoid in `index.web.css` | Reason |
|--------------------------|--------|
| Global `input`/`select`/`textarea` tag selectors from legacy CSS | Fights future shadcn Input (Pitfall 4) |
| Entire `.gsd-btn` / form chrome dump as permanent web system | Dual systems forever |
| Accidental dual import of both CSS entries | Token wars + FOUC |

### Required split

| File | Contents |
|------|----------|
| `src/index.web.css` | Tailwind + tw-animate + shadcn tokens + dark variant + base border/body |
| `src/index.desktop.css` | Current `index.css` moved intact (`gsd-*`, form tags, modals, grid) |
| Bootstrap | `main.tsx` selects CSS via `VITE_PLATFORM` (prefer `@platform-css` alias static import) |

### Shared code discipline

- `ConfigApp`, sections, backends, `preferencesCore` — **no visual restyle** this phase.
- `FormControls.tsx` — **untouched**.
- Theme logic may change only for dual-write in `theme.ts`.
